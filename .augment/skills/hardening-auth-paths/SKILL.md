# Hardening Auth Paths (versola)

Project-specific security invariants for versola's OAuth/OIDC implementation. This is not a
generic OWASP primer — it documents the actual patterns in this codebase, where they're
correct, and where a known gap or inconsistency exists so it isn't silently copied into new
code.

## Quick Reference

| Concern | versola pattern | File |
|---|---|---|
| Password hashing | Argon2id (19 MiB, t=2, p=1), admission-controlled by `zio.Semaphore` sized by `Argon2Config.maxConcurrent` (default 12 ≈ 228 MiB) | `util/.../SecurityService.scala` |
| Secret/token comparison (correct) | `MessageDigest.isEqual` for client/resource secrets | `central/.../ResourceService.scala` |
| Password hash comparison (exception) | `MAC === MAC` → `java.util.Arrays.equals`, **not constant-time** | `util/.../ByteArrayNewType.scala`, used by `PasswordService.check` |
| PKCE verify (exception) | SHA-256 + Base64URL then `encoded == codeChallenge`, plain `String` equality | `AuthorizationCodeRecord.verify` |
| Rate limiting | `SubmissionLimiter.tryAcquire`/`recordLimit`, keyed by `(clientId, subject, challengeType)` | `oauth/conversation/limit/SubmissionLimiter.scala` |
| Rate limiting gap | Passkey assertion records IP as a subject; password submit only uses credential/login, no IP | `ConversationService.scala` (see `PasskeyAssertion` vs `PasswordSubmit` call sites) |
| JWT signing | RS256 via nimbus-jose, key generated by `SecurityService.generateRsaKeyPair`, `keyId` = UTC timestamp | `util/.../JWT.scala` |
| Secrets/config | Typed `Secret.BytesN` newtypes in `CoreConfig`, injected via env vars | `scripts/gen-env.scala` |
| Dependency hygiene | No `sbt-dependency-check` / Scala Steward wired into CI today | — |

## Password Hashing & Admission Control

- Never call Argon2 directly. Go through `SecurityService.hashPassword`, which holds the
  hashing semaphore for the duration of the call.
- Each in-flight hash costs ~19 MiB of heap on ZIO's unbounded blocking pool. If you add a new
  code path that hashes passwords (bulk import, migration script, etc.), it **must** go through
  the same semaphore-gated `SecurityService`, or route through a bounded worker pool — never a
  raw loop over `Argon2BytesGenerator`.
- Raising `Argon2Config.maxConcurrent` without raising the container's memory limit is an OOM
  vector. If a change needs more throughput here, treat it as a memory-budget change, not a
  one-line config tweak — ask first.

## Timing & Comparison Safety

versola's rule for anything derived from a secret (password hash, client secret, resource
secret, MAC) is: **compare with `MessageDigest.isEqual`, never `==` or `Arrays.equals`.**
`ResourceService.scala` follows this correctly — copy that pattern for new comparisons.

Two existing paths do **not** follow it and are known, accepted exceptions — do not treat them
as the pattern to copy:

- `MAC === MAC` resolves to `java.util.Arrays.equals` (see `ByteArrayNewType.given Equal[Type]`).
  Used in `PasswordService.check`. Accepted because the comparison follows a ~50ms+ Argon2id
  hash; that cost dwarfs any timing signal from a 32-byte array compare.
- `AuthorizationCodeRecord.verify` compares the PKCE challenge with plain `String ==`.

If you add a **new** comparison of a secret, hash, or token, it does not get this exception by
default — use `MessageDigest.isEqual`. If you're tempted to reuse `MAC === MAC` outside a
password-verification-style path, ask first.

## Rate Limiting (`SubmissionLimiter`)

- `tryAcquire` checks and charges an attempt atomically; `recordLimit`/`recordLimitAll` charge
  without checking (used post-hoc, e.g. after a failed OTP submit) and short-circuit once a
  subject is already banned — see the comment in `PostgresChallengeThrottleRepository` on why
  (avoids a lock convoy on the same row from an attacker hammering a banned credential).
- Subjects are per-`ChallengeType`. `PasskeyAssertion` includes the client IP as a subject
  alongside the credential; `PasswordSubmit` currently only uses the credential/login subjects
  (see the `subjects` list built in `ConversationService`). This is a known, tracked gap, not a
  model to follow — if you're touching `PasswordSubmit` rate limiting, ask whether IP should be
  added rather than assuming its absence is intentional.
- Adding a new `ChallengeType` requires wiring it into `SubmissionLimits` config and the
  `windowLimits` match in `SubmissionLimiter`. The match has no wildcard case, so a forgotten
  case is only a non-exhaustive-match *warning* (the build has no `-Werror`/`-Xfatal-warnings`)
  and fails at runtime with a `MatchError` the first time that challenge type is evaluated —
  it will not be caught by CI.

## Token Issuance (JWT / PKCE)

- All signing/hashing/key generation goes through `util/JWT.scala` and `SecurityService` —
  never call `com.nimbusds.*` or `Argon2BytesGenerator` directly from service code.
- `Signature.Symmetric` (MACSigner) and `Signature.Asymmetric` (RSASSASigner, RS256) are the
  only two signer paths `JWT.serialize` supports; anything else throws
  `IllegalArgumentException` at runtime, not at compile time — don't add a third signature
  variant without also extending the `match` in `JWT.serialize`.
- PKCE only supports `S256` (`CodeChallengeMethod` enum) — `plain` was removed; don't reintroduce
  it without an explicit RFC 7636 §7.2 downgrade-attack review.

## Secrets & Config

- New secrets belong in `CoreConfig` as `Secret.BytesN` (16 or 32 bytes), not raw `String`.
  Wire them through `scripts/gen-env.scala` with an env-var override, following the
  `ARGON2_MAX_CONCURRENCY` pattern (default in the template + `$${?ENV_VAR}` override).
  Never hardcode a secret value in `gen-env.scala` itself.
- Never log a `Secret`, `MAC`, `Password`, or raw Argon2 pepper/salt. If a new log statement
  touches a value typed as one of these, that's a signal to stop and check whether it needs
  `.toString`-suppression or should be logging an ID instead.

## Ask First

- Adding a new comparison of a secret/hash/token that doesn't use `MessageDigest.isEqual`.
- Raising `Argon2Config.maxConcurrent` or any Argon2 parameter (memory/iterations/parallelism).
- Adding a new `ChallengeType` or changing `SubmissionLimits` semantics.
- Adding a new JWT signature type or PKCE challenge method.
- Adding a dependency that touches crypto, JWT, or password hashing (nimbus-jose, bouncycastle,
  commons-codec are the existing ones — don't add a second library for the same job).

## Never Do

- Never call `Argon2BytesGenerator`, `com.nimbusds.*` signers, or perform encryption via raw
  `Cipher` outside `SecurityService.scala` / `JWT.scala`. (`MessageDigest.isEqual` for secret
  comparisons is the exception — that one belongs at the call site, see Timing & Comparison
  Safety above.)
- Never compare a new secret/hash/token with `==`, `.equals`, or `Arrays.equals`.
- Never store or log a plaintext password, refresh token, or authorization code.

## Red Flags

- A new `.hashPassword` / `.mac` call site outside `SecurityService.Impl`.
- A new `==` comparison whose operands are typed `MAC`, `Secret`, `Digest`, or the raw bytes
  extracted from one.
- A rate-limit or throttle check added without going through `SubmissionLimiter`.
- A new grant type, signature algorithm, or PKCE method added by pattern-matching around
  `JWT.serialize` or `AuthorizationCodeRecord.verify` instead of extending them.
