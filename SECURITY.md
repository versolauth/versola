# Security policy

## Reporting a vulnerability

Please **do not open a public issue** for a security problem.

Report it privately through GitHub: the repository's **Security** tab →
**Report a vulnerability** (private vulnerability reporting). Include what you found, how to
reproduce it, the affected version or commit, and the impact you expect.

Targets we hold ourselves to (best effort until a response process is formalised, #477):

| Step | Target |
|---|---|
| Acknowledge the report | 3 business days |
| Initial assessment and severity | 10 business days |
| Fix or mitigation for critical/high | 30 days |
| Coordinated disclosure | agreed with the reporter, normally after a fix is released |

## Supported versions

Only the latest release receives security fixes. Deployments pin an image tag
(`ghcr.io/versolauth/versola-*`); upgrade with `versola-cli` as described in
[`deploy.md`](deploy.md#4-deploying-a-new-version).

## Scope

In scope: `auth`, `central`, `edge`, the admin console, the container images, the Helm chart
and the compose bundles generated by `versola-tools`.

Out of scope: findings that need a compromised host or administrator account, missing
security headers on non-production example configs, and denial of service by volume alone.

## What to expect from us

We credit reporters who want it, publish a GitHub security advisory for fixed
vulnerabilities, and do not take action against good-faith research that follows this policy.
